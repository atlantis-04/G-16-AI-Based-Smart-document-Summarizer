# Self-Healing RAG Pipeline — Project Context

## What This Project Does
A Retrieval-Augmented Generation system that critiques its own output and retries.
Uses LangGraph to model a stateful cyclical workflow.

## Stack
- Backend: FastAPI + LangGraph + ChromaDB + OpenAI/Groq
- Frontend: HTML/CSS/JS (to be expanded)
- Deployment: Docker + docker-compose

## API Endpoints

### Health & Status
- **GET /** → API info (message, docs link, version)
- **GET /health** → Health check + document count + active model
  - Response: `{status, collection_count, model}`

### Query Processing (Self-Healing RAG)
- **POST /query** → Submit a question, get self-healing answer
  - Request: `{query: str, max_results: int = 5}`
  - Response: `{final_answer, critique, retry_count, retrieved_chunks, is_grounded, query}`
  - Auto-retries up to 3 times if answer not grounded

### Document Ingestion
- **POST /ingest** → Add documents to vector database
  - Request: `{texts: list[str], metadatas: list[dict] = []}`
  - Response: `{chunks_added: int, message: str}`

### Auto-Generated Documentation
- **GET /docs** → Swagger UI (auto-generated by FastAPI)
- **GET /redoc** → ReDoc UI (alternative API documentation)

## Groq Setup
- **Default LLM**: llama-3.1-8b-instant via Groq (free tier)
- **Fallback**: gpt-4o-mini via OpenAI
- **Get free Groq API key**: https://console.groq.com
- Set `USE_GROQ=True` in .env to use Groq (default), set to `False` for OpenAI

## LangGraph Architecture
- **Nodes**: retrieve → generate → critic → (conditional) → finalize or retrieve
- **State**: TypedDict `RAGState` flows through all nodes with:
  - Query info (query, reformulated_query)
  - Retrieval data (retrieved_chunks)
  - Generation data (generated_answer)
  - Criticism (critique, is_grounded, retry_count)
  - Output (final_answer, error)
- **Conditional Edge**: Critic node drives self-healing:
  - If grounded OR max_retries reached → finalize
  - Else → loop back to retrieve with reformulated_query
- **Self-Healing Loop**: Critic suggests better search query for re-retrieval

## Key Design Decisions
- LangGraph manages state as a TypedDict passed between nodes
- Critic agent uses an LLM to evaluate groundedness via JSON response
- Max 3 re-retrieval attempts before graceful fallback
- ChromaDB stores embeddings locally (persisted to disk)
- Plain Settings class (not Pydantic) for lightweight config
- ChromaRetriever uses Sentence Transformers for embeddings
- Dual LLM support: Groq (default, free) and OpenAI (fallback)
- FastAPI with CORS enabled for cross-origin frontend requests
- Comprehensive logging for debugging and monitoring

## Running the API

### Local Development
```bash
# Activate venv
source .venv/bin/activate

# Set environment variables
cp .env.example .env
# Edit .env with your API keys

# Run the server
python -m backend.main

# Or using uvicorn directly
uvicorn backend.main:app --reload
```

Server runs on http://localhost:8000

### Frontend Setup
The frontend is a single HTML file that can be served in multiple ways:

**Option 1: Direct file open (no server needed)**
```bash
# Simply open the file in your browser
open frontend/index.html
# Or on Linux
xdg-open frontend/index.html
```

**Option 2: Simple Python HTTP server**
```bash
# From project root
python -m http.server 3000
# Then visit http://localhost:3000/frontend/index.html
```

**Option 3: Using Live Server (VS Code extension)**
- Install "Live Server" extension
- Right-click frontend/index.html → "Open with Live Server"

**Option 4: Production setup (nginx/Docker)**
- Copy frontend/index.html to your web server
- Ensure API_BASE in JavaScript points to your API server
- Deploy alongside backend or to separate domain (CORS already enabled)

### Complete End-to-End Setup
```bash
# Terminal 1: Start the API backend
source .venv/bin/activate
python -m backend.main
# Backend runs on http://localhost:8000

# Terminal 2: Serve the frontend
cd frontend
python -m http.server 3000
# Frontend runs on http://localhost:3000

# Open browser to: http://localhost:3000/index.html
```
